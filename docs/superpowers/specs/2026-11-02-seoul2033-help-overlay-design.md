# Seoul 2033 Help — 오버레이 답지 설계

**날짜:** 2026-11-02  
**상태:** 승인된 동작 설계 (비주얼 UI 스킨은 후속)  
**저장소:** https://github.com/bossxor/Seoul_2033_Help

## 1. 목적

서울 2033 플레이 중 나무위키에 정리된 랜덤 인카운터·선택지·결과를, 게임 위(또는 PC 옆자리)에서 바로 보게 한다.

핵심 경험:

1. 지금 어떤 스토리/인카운터인지 표시
2. 선택지를 모두 표시
3. 각 선택지가 어떤 결과인지 표시 (아이템·능력·상태·수치·**확률** 구분)
4. 손은 게임만 사용. 오버레이는 읽기 위주이며, 화면 OCR로 장면을 동기화

비주얼 디자인(색, 타이포, 스킨)은 이 문서 범위 밖이다. 이후 UI 스킬로 별도 진행한다. 본 문서는 **무엇을·어떤 순서로·어떤 데이터로** 할지 고정한다.

## 2. 범위와 우선순위

### 한다 (MVP → 확장)

| 순위 | 항목 |
|------|------|
| 1 | 공유 인카운터 그래프 스키마 + 시드 데이터(소량부터, 목표는 전부) |
| 2 | Android 전체화면: 검색 + 선택 트리 따라가기 + 결과 표시 |
| 3 | Android 오버레이: 인카운터명·선택지·결과, 재OCR 동기화, **투명도 조절**, **닫기=앱 완전 종료** |
| 3b | OCR **영역 크롭**(선택지 쪽) + 매칭 **신뢰도/후보 목록** |
| 4 | 런타임 AI 해독(미스 시) + 기기 로컬 캐시 누적 |
| 5 | Web(PC): 같은 시드, 검색·트리만 (OCR/오버레이 없음) |

### 하지 않는다 (이 설계 단계)

- 클라우드 동기화 / 다중 유저 공유 DB
- 게임 버튼 좌표 탭 후킹
- **보유 가젯 조건 필터** (안 쓰면 이득 없음. 필요해지면 후속)
- 추천 기준 프리셋(생존/아이템 등) — 단일 `recommend`만
- 스토어 배포·과금·계정
- 비주얼 브랜딩·애니메이션 폴리시 (후속 스킬)

### 콘텐츠

- 목표: 나무위키 랜덤 인카운터 **전부** (기본·주요 스토리·확장팩·시즌 등)
- 실현: 시드를 단계적으로 채움. 앱 기능 완성도와 콘텐츠 완성도를 분리한다.
- 출처: 나무위키 등. 재배포 시 라이선스(CC BY-NC-SA 등)·출처 표기를 앱/문서에 명시한다. 개인·비상업 전제.

## 3. 아키텍처

```
[data/encounters 시드] ──┬── Android 앱 (우선)
                         └── Web 앱 (나중, 검색만)

Android 런타임:
  MediaProjection/캡처 → OCR(한국어)
       → Matcher(선택지·제목 fuzzy)
       → EncounterStore(시드 ∪ 로컬 AI 캐시)
       → Overlay UI (읽기 전용 위주)

미스 시(옵션):
  OCR/검색 텍스트 → AI 구조화 → 로컬 캐시 append
  (ADB로 캐시 export → 검수 후 시드에 merge → git)
```

### 클라이언트 역할

| 클라이언트 | 역할 |
|------------|------|
| Android | OCR 오버레이 + 전체화면 검색/트리 + 로컬 AI 캐시 |
| Web(PC) | 같은 콘텐츠 검색·트리·결과 표시. OCR·오버레이·로컬 AI 캐시 없음 |

공유하는 것: **시드 데이터와 스키마(내용)** 뿐이다. 플랫폼 UI 코드는 공유하지 않아도 된다.

### 기술 방향 (구현 시 확정 가능, 의도만 고정)

- Android: Kotlin, Jetpack Compose, 오버레이용 `SYSTEM_ALERT_WINDOW` + 화면 캡처 권한, OCR은 ML Kit(또는 동급 한국어 OCR)
- Web: 정적/간단 SPA + 시드 JSON (프레임워크는 플랜 단계에서 최소 선택)
- 시드: `data/` 아래 버전 있는 JSON(또는 빌드 시 SQLite 생성). git 관리

## 4. 데이터 모델

인카운터는 **장면 그래프**다. 노드 = 한 화면/분기 지점, 엣지 = 선택지.

### 4.1 EncounterNode

| 필드 | 설명 |
|------|------|
| `id` | 안정적 ID (슬러그) |
| `title` | 인카운터/장면 이름 (오버레이 상단 표시) |
| `story` | 스토리/카테고리 (기본, 주요 스토리, 확장팩명 등) |
| `body` | 선택 (장면 설명 요약) |
| `choices` | Choice 배열 |
| `source` | 출처 메모 (위키 문단 등) |
| `updatedAt` | 시드/캐시 갱신 시각 |

### 4.2 Choice

| 필드 | 설명 |
|------|------|
| `text` | 게임/위키에 보이는 선택지 문구 (매칭 키) |
| `effects` | Effect 배열 (한 선택지에 결과 여러 개 가능) |
| `nextId` | 다음 노드 ID. 종료면 null |
| `recommend` | 선택. 기본 추천 힌트(불리언 또는 짧은 이유 코드) |

### 4.3 Effect (결과 타입 구분 — 필수)

타입이 섞이지 않게 구분한다.

| `type` | 의미 | 예 |
|--------|------|----|
| `item` | 아이템 획득/손실 | 상비약 +1 |
| `ability` | 능력 획득/손실 | 날렵함 |
| `status` | 상태 이상/플래그 | 순수한 얼굴 소멸 |
| `resource` | 체력·멘탈·돈·식량 등 칸 자원 | 체력 -1 |
| `chance` | 확률 분기 | successRate 0.44, 성공/실패 결과 |
| `text` | 기타 서술형 결과 | 인카운터 종료, 탈선 |
| `condition` | 선택 가능 조건 | 권총 보유 시만 |

`chance` 예시 형태:

```json
{
  "type": "chance",
  "successRate": 0.44,
  "success": [ { "type": "ability", "name": "날렵함" } ],
  "failure": [ { "type": "resource", "name": "체력", "delta": -1 } ]
}
```

위키 문장 「44% 확률로 성공」은 파서/AI가 `chance`로 넣고, UI는 `44% 성공`처럼 **확률을 다른 결과와 시각적으로 구분**해 보여 준다 (구체 스킨은 후속).

### 4.4 저장소

- **Seed:** `data/encounters*.json` (git). Android·Web 빌드에 포함
- **LocalCache (Android only):** 런타임 AI가 추가한 노드. 기기 내부. export 가능
- **조회:** `Seed ∪ LocalCache` (동일 `id`면 캐시가 덮거나 merge 규칙 명시 — 기본: 캐시 우선)

클라우드 없음. 캐시 → 시드 반영은 개발자가 ADB/파일로 가져와 검수 후 커밋.

## 5. 매칭 · OCR · 동기화

### 5.1 매칭

입력: OCR 문자열 또는 검색어.  
방법: 선택지 `text`·노드 `title`에 대한 정규화(공백·문장부호) + fuzzy 점수.  
출력: 후보 노드 목록 + 점수. 임계값 미만 = 미스 → UI에 `정보 없음`.

선택지 문구만으로도 인카운터 식별이 가능하다는 전제(사용자 확인).

**신뢰도 · 후보 (필수):**

- 최고점 1개를 기본 표시하되, **점수(또는 상대 신뢰도)**를 함께 보여 준다.
- 2위가 최고점과 가깝거나(동점·근소), 최고점이 애매하면 **후보 2~3개**를 목록으로 보여 사용자가 고른다. 오답지 자동 확정 금지.
- 명확한 1등(여유 점수)만 자동 확정.

### 5.1b OCR 영역 크롭 (필수)

- 전체 화면이 아니라 **선택지가 모인 영역**(기본: 화면 하단 비율 크롭)만 OCR한다. 정확도·성능·배터리 이득.
- 크롭 비율/영역은 설정에서 조절 가능(최소: 하단 비율 프리셋 또는 드래그 박스 중 구현 쉬운 쪽).
- 크롭 밖 스토리 본문 노이즈를 줄이는 것이 목적이다.

### 5.2 오버레이 동기화 (읽기 위주)

사용자는 게임에서만 선택한다. 오버레이는 현재 장면의 답지를 보여 준다.

재OCR 트리거:

1. **수동 `인식` 버튼 — 항상 동작** (자동이 켜져 있어도 즉시 스캔)
2. **자동 주기 — 설정 옵션** (N초마다). 기본은 끄는 것을 권장, 사용자가 켠다

자동만으로 「손가락이 누른 버튼」을 추적하지 않는다. 바뀐 화면의 텍스트를 다시 읽어 노드를 맞춘다.

오버레이에서 선택지를 탭해 트리를 진행하는 기능은 **필수 아님**. 필요 시 후순위 옵션.

### 5.3 답지 표시 규칙

오버레이(및 전체화면 상세)에 반드시:

1. `story` + `title` (어떤 스토리의 어떤 인카운터인지)
2. 모든 `choices[].text`
3. 각 선택지의 `effects` 요약 — `chance`는 확률을 명시해 구분
4. **추천(더 나은 선택지) 강조**
   - 추천 토글 ON(기본 권장): `recommend`가 있는 선택지는 **테두리 색을 다르게** 해서 한눈에 구분한다. 아이콘·배지만으로 끝내지 않고, 카드/행 외곽선 대비를 준다.
   - 추천이 여러 개면 모두 같은 강조 테두리. 「최악」별도 등급은 MVP에 없음 (후순위).
   - 토글 OFF: 테두리 강조 없음. 선택지·결과는 그대로 전부 표시.
   - 구체 hex/테마 색은 비주얼 스킨 단계에서 정한다. 동작 요구는 「추천 = 비추천과 다른 border 색」.

미스: `정보 없음`. 이어서 `검색` 또는 `AI 해독`(설정·키 있을 때).

## 6. AI 역할

| 시점 | 역할 |
|------|------|
| 개발/시드 구축 | 나무위키 텍스트 → EncounterNode JSON 구조화. 사람 검수 후 git |
| 런타임 (Android) | 매칭 미스·신규 장면일 때 선택적 호출. 성공 시 LocalCache에 append |

- API 키: 기기 로컬 설정. 없으면 런타임 AI 비활성, `정보 없음` + 검색만
- Web 1차: 런타임 AI 없음 (시드만)
- 품질: 확률·조건·후속 분기 누락이 잦을 수 있음 → 캐시는 시드 merge 전 검수

## 7. Android UI 골격 (스킨 전)

### 오버레이 패널

- 상단: 스토리 / 인카운터명 (애매 매칭 시 후보 목록)
- 본문: 선택지 리스트 + 결과(타입별). 추천 행은 **다른 테두리 색**으로 강조
- 컨트롤: `인식`, `검색` 열기, `추천` 토글, `자동 OCR` 토글(또는 설정), **투명도**, **닫기**
- 상태: 매칭됨(신뢰도) / 후보 선택 필요 / 정보 없음 / OCR 실패 / 권한 필요

**투명도:** 오버레이 패널 배경 알파를 사용자가 조절한다. 값 유지(설정 persist). 글자 가독성 하한은 구현 시 클램프.

**닫기 = 앱 완전 종료:** 오버레이 삭제/닫기 버튼은 패널만 숨기지 않는다. 오버레이 서비스·캡처·관련 액티비티를 정리하고 프로세스를 종료한다 (`finishAffinity` + 서비스 stop, 필요 시 프로세스 종료). 다시 쓰려면 앱 아이콘으로 재실행.

### 전체화면

- 검색, 카테고리(story), 노드 상세(동일 답지 규칙)
- 오버레이가 불편할 때의 폴백

### 권한

- 다른 앱 위에 표시
- 화면 캡처(미디어프로젝션 사용자 동의)
- (자동 OCR 시) 포그라운드 서비스 알림 가능

## 8. Web (후순위)

- PC에서 폰 게임과 병행하는 **검색 답지**
- 시드 JSON 로드, 검색·트리·결과 표시
- OCR·오버레이·로컬 AI 캐시 없음
- Android 시드 갱신과 같은 `data/`를 사용

## 9. 오류 처리

| 상황 | 행동 |
|------|------|
| 오버레이/캡처 권한 거부 | 이유 + 설정 유도. 전체화면 검색은 사용 가능 |
| OCR 실패·빈 텍스트 | `인식 실패` + 재시도 + 검색 유도 |
| 매칭 미스 | `정보 없음` + 검색 + (가능 시) AI 해독 |
| AI 실패·키 없음 | 캐시 추가 안 함. 정보 없음 유지 |
| 시드 로드 실패 | 앱 시작 시 명확한 오류. 빈 답지 방지 |

## 10. 테스트

- **단위:** 문자열 정규화·fuzzy 매칭 (한글, 비슷한 선택지, 부분 문자열)
- **단위:** Effect 요약 포맷 (`chance` 44% vs `item` 구분)
- **단위:** 그래프 `nextId` 이동
- **픽스처:** 시드 샘플 소수로 「선택지 문구 → 노드」골든 테스트
- **수동:** 실기기 OCR, 오버레이 권한, 자동 주기 on/off
- 게임 APK가 있으면 텍스트 렌더 방식 확인(OCR 난이도). 필수는 아님

## 11. 성공 기준

1. 알려진 시드 인카운터에서, OCR 또는 검색으로 노드를 찾고 선택지·결과를 모두 본다
2. 확률 결과가 다른 효과와 구분되어 보인다
3. 추천 토글 ON일 때 추천 선택지는 비추천과 **다른 테두리 색**으로 구분된다
4. OCR은 크롭 영역 기준이며, 애매하면 후보를 고르게 한다
5. 오버레이 투명도 조절이 되고, 닫기 시 앱이 완전히 종료된다
6. 수동 인식으로 장면이 갱신된다. 자동 주기를 켜면 추가 조작 없이 갱신 시도한다
7. 미스 시 `정보 없음`이 뜨고 검색으로 폴백한다
8. (Android) AI 성공 분이 로컬에 남아 export 가능하다
9. Web은 같은 시드로 검색 답지가 된다 (후순위 완료 시)
